Titipin POS & Order Management

Buku Panduan Arsitektur, Alur Data, dan Dokumentasi Teknis Terlengkap untuk Junior hingga Lead Developer.

👋 Selamat Datang di Handboook Pengembang Titipin! Dokumen ini disusun sedemikian rupa agar siapa pun—bahkan yang baru pertama kali menyentuh proyek ini—bisa memahami dengan jelas apa saja yang ada di dalam repository, cara kerja setiap baris kode, hingga panduan praktis jika ingin melakukan modifikasi dari yang paling sepele hingga yang paling kompleks.

1. The Big Picture (Gambaran Besar Sistem)

Titipin adalah sistem Point-of-Sale (POS) & Order Management modern yang dirancang khusus untuk industri retail cepat (supermarket, minimarket, toko oleh-oleh, atau grosir) dengan beban transaksi tinggi.

⚡ Latency-Critical POS

Kasir harus bisa memproses barang dalam hitungan milidetik. Pencarian produk menggunakan PostgreSQL GIN Trigram index, shortcut keyboard (F2 cari barang, F3 pilih member), dan kalkulator pembayaran tunai instan.

🔒 Integritas Data ACID

Setiap transaksi penjualan dijalankan dalam database transaction terisolasi. Jika 1 dari 10 barang gagal stoknya, seluruh transaksi dibatalkan (rollback) tanpa sisa.

📊 Observability Terbina

Sistem dilengkapi monitoring bawaan Prometheus dan Grafana auto-provisioned untuk mendeteksi lonjakan traffic, kebocoran memori, dan latensi query secara real-time.

2. Anatomi Monorepo (Struktur Folder Proyek)

Proyek ini menggunakan arsitektur Monorepo berbasis pnpm workspaces dan diorkestrasi oleh Turborepo. Semua aplikasi dan shared library berada dalam satu repositori yang rapi.

Direktori / File Tipe Tanggung Jawab & Fungsi Utama
apps/frontend/ Next.js 15 App Aplikasi web user-interface: halaman kasir POS, katalog produk, member, dashboard penjualan, struk kasir, dan analitik bisnis.
apps/backend/ NestJS 11 App REST API Server: business logic, validasi transaksi kasir, kalkulasi order, hashing password, otorisasi JWT, dan integrasi database Drizzle.
packages/shared/ Shared NPM Package Tempat skema validasi Zod, TypeScript Interfaces, DTOs, dan Enums yang dipakai bersamaan oleh Frontend dan Backend (mencegah duplikasi tipe).
packages/eslint-config/ Shared Tooling Konfigurasi sentral ESLint 9 Flat Config untuk memastikan seluruh monorepo mengikuti gaya penulisan kode yang seragam.
packages/typescript-config/ Shared Tooling Base tsconfig.json strict mode untuk Next.js dan NestJS.
monitoring/ DevOps / Infra Konfigurasi Prometheus (prometheus.yml) dan Grafana provisioning (datasource & dashboard JSON).
docker-compose.yml DevOps Konfigurasi multi-container untuk menjalankan PostgreSQL dan Redis/App di lokal secara cepat.
docker-compose.prod.yml Production Infra Stack lengkap production: Frontend, Backend, Postgres, Prometheus, dan Grafana dalam satu network.

3. Tech Stack & Keputusan Rekayasa

Kenapa stack ini yang dipilih? Mengapa bukan alternatif lain?

Next.js 15 + React 19 (Frontend)

Alasan: Menggunakan App Router untuk routing berbasis file yang intuitif, Tailwind CSS untuk styling responsif tanpa CSS runtime overhead, dan TanStack Query (React Query) untuk caching data produk dan kasir yang agresif di memori browser.

NestJS 11 + Drizzle ORM (Backend)

Alasan: NestJS menyediakan arsitektur enterprise berbasis Dependency Injection, Module, Guard, dan Interceptor. Drizzle ORM dipilih karena berkali-kali lipat lebih ringan dan cepat daripada TypeORM/Prisma, menghasilkan query SQL transparan tanpa *query engine binary* yang berat.

PostgreSQL 16 + pg_trgm

Alasan: Database relasional terandal di dunia dengan dukungan GIN Trigram index untuk pencarian teks fuzzy barcode dan nama produk dalam waktu < 2 milidetik.

Prometheus + Grafana

Alasan: Standar de-facto observability hemat resource (~90MB RAM total di server), bebas biaya SaaS bulanan, dan auto-provisioned via code.

4. Alur Autentikasi & Proteksi Rute (Auth Cycle)

Titipin menerapkan standar keamanan ganda: JWT Access Token (masa aktif pendek 15 menit) dan Refresh Token (masa aktif 7 hari) yang disimpan dalam cookie terproteksi.

1. User input Email & Password di /login
→ POST /api/auth/login →
2. Backend verifikasi Bcrypt hash
↓ Jika Valid
3. Backend terbitkan Access Token & Refresh Token Cookie
→ Simpan sesi →
4. Frontend simpan Access Token di memori & redirect ke /dashboard
↓ Setiap Navigasi Halaman
5. Next.js Middleware (apps/frontend/src/middleware.ts)
Cek keberadaan refresh_token cookie
→ Jika tidak ada →
Redirect balik ke /login
⚠️ Catatan Penting untuk Junior Developer mengenai Cookie & HTTP: Saat dideploy ke server tanpa SSL HTTPS (plain HTTP seperti http://100.85.157.52), atribut cookie secure: true akan otomatis DITOLAK oleh browser modern seperti Chrome dan Brave. Oleh karena itu, backend kita memiliki flag COOKIE_SECURE=false pada file environment production non-HTTPS agar cookie tetap bisa disimpan.

5. Alur Transaksi Kasir POS (Checkout Lifecycle)

Inilah "jantung" dari seluruh aplikasi retail Titipin. Bagaimana satu transaksi dari kasir diproses sampai struk keluar?

  1. Pencarian & Penambahan Produk: Kasir menekan F2 untuk fokus ke input pencarian, lalu mengetik nama atau scan barcode. Produk diklik atau di-enter untuk masuk ke keranjang kasir (state lokal dikelola oleh hook usePosCart di apps/frontend/src/hooks/use-pos-cart.ts).
  2. Pilihan Pelanggan: Secara default kasir mencatat sebagai Pelanggan Umum (Walk-in). Jika pembeli adalah member, kasir menekan F3 untuk memilih member dan mendapatkan poin/riwayat.
  3. Buka Modal Pembayaran: Kasir menekan tombol Bayar Sekarang. Modal pembayaran tunai muncul dengan tombol cepat: Uang Pas, 50.000, 100.000, 200.000. Sistem menghitung uang kembalian secara otomatis.
  4. Eksekusi API Atomic Transaction: Frontend mengirim payload POST /api/orders/checkout:
    POST /api/orders/checkout
    {
  "customer_id": "uuid-pelanggan-atau-null",
  "paid_amount": 50000,
  "items": [
    { "product_id": 1, "quantity": 2 },
    { "product_id": 4, "quantity": 1 }
  ]
}
  5. Validasi & Eksekusi di Backend (OrdersService):
    • Backend membuka transaksi SQL: db.transaction(async (tx) => { ... }).
    • Sistem mengunci baris produk dengan lock database untuk mencegah race condition jika ada dua kasir checkout bersamaan.
    • Sistem memeriksa apakah stock >= quantity. Jika ada satu item saja yang stoknya kurang, seluruh transaksi di-ROLLBACK seketika dengan error status 422.
    • Sistem mengambil harga snapshot saat itu (unit_price) dari database master produk (harga tidak pernah dipercaya dari client/frontend).
    • Sistem meng-generate nomor invoice unik dengan format INV-YYYYMMDD-XXXX.
    • Mengurangi stok master produk: UPDATE products SET stock = stock - quantity.
    • Mencatat log audit ke tabel order_activity_logs dan audit_logs.
  6. Penerbitan Struk: Backend mengembalikan detail order lengkap. Frontend membuka popup struk faktur kasir interaktif yang mendukung format cetak printer kasir 58mm & 80mm, unduh dokumen PDF, atau unduh gambar struk.

6. Skema Database & Relasi (Drizzle ORM)

Seluruh definisi skema database ditulis secara deklaratif menggunakan TypeScript di direktori apps/backend/src/database/schema/.

Nama Tabel File Skema Kolom Kunci & Fungsi
users users.schema.ts Data staf kasir dan super admin (id, name, email, password hash, role enum: admin | cashier).
products products.schema.ts Katalog produk (id, product_code, product_name, stock, price, deleted_at). Menggunakan GIN Trigram index untuk search instan.
customers customers.schema.ts Data member/pelanggan (id UUID, customer_name, customer_address, gender, birth_date, phone, deleted_at).
orders orders.schema.ts Header transaksi penjualan (id, order_number unik INV-..., customer_id, created_by staf kasir, order_date, total_amount, paid_amount, change_amount).
order_items orders.schema.ts Rincian item barang dalam setiap order (id, order_id, product_id, quantity, unit_price harga snapshot, subtotal).
draft_orders orders.schema.ts Fitur transaksi kasir yang ditahan sementara (Hold Order) jika pelanggan ingin mengambil barang tambahan.
order_activity_logs orders.schema.ts Pencatatan riwayat perubahan status transaksi (created, finalized, cancelled).
audit_logs audit.schema.ts Log keamanan sistem mencatat aksi penting staf (user login, tambah produk, hapus member, ubah data).
💡 Mengapa Ada Kolom `unit_price` di `order_items`? Harga produk di tabel products bisa saja naik atau turun minggu depan. Kolom unit_price di order_items mengunci harga saat barang itu dibeli pada detik transaksi terjadi. Dengan begitu, laporan keuangan masa lalu tidak akan pernah berubah atau kacau.

7. Observability Stack (Prometheus & Grafana)

Titipin menyertakan monitoring kelas enterprise yang langsung siap digunakan tanpa konfigurasi manual.

Prometheus (:9090)

Bertindak sebagai Metric Scraper & Time-Series Database. Setiap 15 detik, Prometheus memanggil http://backend:3001/api/metrics untuk menarik metrik CPU, Memory, Event Loop Lag, HTTP request rate, dan database pool.

Grafana (:3002)

Bertindak sebagai Visualization Dashboard. Seluruh panel grafik otomatis terkonfigurasi via file monitoring/grafana/dashboards/titipin-overview.json (Infrastructure-as-Code). Akun default: admin / Admin123!.

8. Bedah Modul Backend Service (NestJS)

Backend dibangun menggunakan Clean Modular Architecture di dalam apps/backend/src/modules/:

  • auth/: Menangani login staf kasir, penerbitan JWT Access/Refresh token, dan hashing password Bcrypt.
  • orders/: Menangani proses checkout transaksi penjualan, hold/draft order, kalkulasi subtotal, pengurangan stok, dan ekspor data penjualan ke CSV/Excel.
  • products/: Manajemen katalog produk (CRUD), soft-delete produk, validasi stok, pencarian kode barcode.
  • customers/: Manajemen data pelanggan dan member toko (CRUD), pencarian nama pelanggan.
  • dashboard/: Mengagregasi metrik cepat (omset hari ini, total transaksi, top 5 produk terlaris, notifikasi stok kritis <5).
  • analytics/: Modul Business Intelligence tingkat lanjut: grafik omset & laba bersih, heatmap jam sibuk kasir, algoritma saran bundling barang, dan segmentasi pelanggan RFM (Recency, Frequency, Monetary).
  • audit/: Modul audit trail untuk mencatat siapa melakukan apa di sistem.
  • health/: Endpoint health check (/api/health) dan Prometheus metrics (/api/metrics).

9. Bedah Modul Frontend Service (Next.js 15)

Frontend dibangun menggunakan Next.js 15 App Router di dalam apps/frontend/src/:

  • app/(auth)/login/: Halaman login kasir yang bersih dengan penanganan pesan error yang informatif.
  • app/(dashboard)/layout.tsx: Layout utama dashboard dengan sidebar responsif dan top navbar profil staf.
  • app/(dashboard)/pos/: Layar utama kasir kasir POS: katalog barang dengan filter kategori, keranjang belanja instan, tombol pintas F2 & F3, serta modal cetak struk kasir.
  • app/(dashboard)/products/: Tabel inventaris barang dengan form tambah/edit modal, pagination, dan konfirmasi soft-delete.
  • app/(dashboard)/customers/: Tabel member pelanggan dengan filter pencarian dan riwayat belanja.
  • app/(dashboard)/orders/: Tabel riwayat seluruh transaksi penjualan dengan filter rentang tanggal, filter kasir, dan cetak ulang invoice.
  • app/(dashboard)/analytics/: Visualisasi analitik bisnis dilengkapi Info Tooltips yang menjelaskan formula perhitungan di setiap metrik kartu.
  • app/(dashboard)/audit-logs/: Halaman log aktivitas audit untuk super admin.

10. Shared Library (@titipin/shared)

Terletak di packages/shared/. Ini adalah "kontrak bersama" antara frontend dan backend:

  • src/schemas/: Skema validasi runtime berbasis Zod (misal: CreateProductSchema, CheckoutOrderSchema). Validasi yang sama persis dijalankan di browser kasir dan di server backend.
  • src/types/: Tipe TypeScript murni yang di-infer otomatis dari skema Zod (misal: Product, Customer, Order).
  • src/enums/: Enumerasi status (UserRole: admin vs cashier, OrderStatus, Gender).

11. Cheat Sheet: "Mau Ubah Apa? Di Mana Letaknya?"

Bagian ini adalah panduan penyelamat bagi junior developer. Ketik kata kunci di bawah untuk mencari file dan baris yang perlu diedit!

🏪 Mau Ganti Nama Toko, Alamat, atau No. Telepon di Struk Kasir?

apps/frontend/src/app/(dashboard)/pos/page.tsx

Buka file tersebut dan cari bagian modal Transaksi Berhasil (sekitar baris 400–450). Di sana terdapat teks nama toko: TITIPIN POS, alamat Jl. Pajajaran No. 128, Bogor, dan telepon 0251-888999. Anda bisa mengubahnya langsung ke nama toko Anda.

🎨 Mau Ganti Logo Toko di Sidebar dan Halaman Login?

apps/frontend/src/components/layout/sidebar.tsx & apps/frontend/src/app/(auth)/login/page.tsx

Komponen logo menggunakan ikon dari lucide-react (ikon Store atau ShoppingBag) dengan teks Titipin POS. Jika ingin mengganti dengan gambar PNG/SVG kustom, letakkan file logo di apps/frontend/public/logo.png dan ganti dengan komponen <Image src="/logo.png" ... />.

📦 Mau Tambah Kolom Baru di Tabel Produk (misal: `expired_date` atau `category`)?

Langkah 4 File: schema.ts → @titipin/shared → repository → frontend

1. Tambah kolom di apps/backend/src/database/schema/products.schema.ts.

2. Jalankan di terminal backend: pnpm db:generate untuk membuat file migrasi SQL baru di apps/backend/drizzle/.

3. Update Zod Schema di packages/shared/src/schemas/products.schema.ts agar input divalidasi.

4. Update form modal tambah/edit produk di apps/frontend/src/app/(dashboard)/products/page.tsx.

⌨️ Mau Ubah Tombol Shortcut Kasir (misal: bukan F2 atau F3)?

apps/frontend/src/app/(dashboard)/pos/page.tsx

Cari fungsi handleKeyDown di dalam useEffect. Anda akan menemukan pengecekan e.key === 'F2' untuk fokus ke input pencarian barang, dan e.key === 'F3' untuk membuka modal pemilih member/pelanggan.

💰 Mau Ubah Format Mata Uang (Rupiah)?

apps/frontend/src/lib/utils.ts

Cari fungsi formatRupiah(amount: number). Fungsi ini menggunakan Intl.NumberFormat('id-ID', { style: 'currency', currency: 'IDR' }). Jika ingin memodifikasi tampilan pecahan atau simbol mata uang, ubah di fungsi ini.

🔑 Mau Ubah Masa Berlaku Token Login (JWT Expired)?

apps/backend/src/config/env.config.ts & apps/backend/.env

Ubah variabel JWT_EXPIRES_IN (default: 15m untuk access token) dan JWT_REFRESH_EXPIRES_IN (default: 7d untuk refresh token cookie).

👤 Mau Ganti Akun Default Admin / Kasir di Seeder?

apps/backend/src/database/seeds/index.ts

Cari array akun di bagian awal seeder. Default akun saat ini adalah:
• Super Admin: admin@titipin.id / Admin123!
• Staff Kasir: kasir@titipin.id / Kasir123!
Ubah email, nama, atau password di file tersebut, lalu jalankan pnpm db:seed.

⚠️ Mau Ubah Batas Notifikasi Stok Menipis (sekarang < 5)?

apps/backend/src/modules/dashboard/dashboard.service.ts & apps/frontend/...

Cari klausa query SQL lt(products.stock, 5) di backend. Jika Anda ingin produk dianggap menipis bila stoknya di bawah 10, ubah angka 5 menjadi 10.

🔌 Mau Ubah Port Aplikasi (Frontend, Backend, atau Grafana)?

docker-compose.yml & apps/backend/.env & apps/frontend/.env

Port default sistem:
• 3000: Frontend Next.js (ubah di docker-compose.yml atau flag next dev -p XXXX).
• 3001: Backend NestJS (ubah di PORT=3001 file .env).
• 3002: Grafana Dashboard.
• 9090: Prometheus Server.
• 5432: PostgreSQL Database.

📈 Mau Ubah Rumus Analitik Bisnis atau Teks Penjelasan Tooltip?

apps/backend/src/modules/analytics/ & apps/frontend/src/app/(dashboard)/analytics/page.tsx

Logika perhitungan AOV (Average Order Value), Gross Profit, dan Segmentasi RFM berada di analytics.service.ts. Teks penjelasan pada icon info tooltip berada di file frontend analytics/page.tsx di dalam komponen <InfoTooltip content="..." />.

12. Tutorial Step-by-Step Menambah Fitur Baru

Misalkan manajer toko meminta Anda membuat fitur baru: "Diskon Kupon Promosi (Vouchers)". Bagaimana urutan kerja yang benar di monorepo ini?

Ikuti Prinsip "Database-First, Contract-Next, Implementation-Last": Jangan mulai dari coding tampilan UI! Mulailah dari skema database, lalu buat kontrak tipe di shared package, implementasikan endpoint backend, dan terakhir hubungkan ke frontend.
  1. Langkah 1: Buat Skema Database Buat file baru apps/backend/src/database/schema/vouchers.schema.ts: 
    export const vouchers = pgTable('vouchers', {
  id: uuid('id').defaultRandom().primaryKey(),
  code: varchar('code', { length: 50 }).notNull().unique(),
  discountPercent: integer('discount_percent').notNull(),
  isActive: boolean('is_active').default(true),
  expiresAt: timestamp('expires_at', { withTimezone: true }),
});
    Daftarkan file tersebut di apps/backend/src/database/schema/index.ts, lalu jalankan: 
    cd apps/backend && pnpm db:generate
  2. Langkah 2: Daftarkan Kontrak di Shared Package Buka packages/shared/src/schemas/ dan buat vouchers.schema.ts dengan validasi Zod. Ekspor tipenya di packages/shared/src/index.ts, lalu jalankan: 
    cd packages/shared && pnpm build
  3. Langkah 3: Buat Module di Backend (NestJS) Jalankan atau buat folder di apps/backend/src/modules/vouchers/ berisi:
    • vouchers.controller.ts (menerima HTTP GET/POST).
    • vouchers.service.ts (logika verifikasi kupon).
    • vouchers.module.ts (daftarkan ke app.module.ts).
  4. Langkah 4: Hubungkan ke Frontend (Next.js) Buka apps/frontend/src/app/(dashboard)/, buat folder baru vouchers/page.tsx. Gunakan apiClient dari @/lib/api-client untuk memanggil endpoint yang baru saja Anda buat. Daftarkan menu baru tersebut di apps/frontend/src/components/layout/sidebar.tsx.

13. Kamus Error & Solusi Masalah Populer (Troubleshooting)

Daftar kendala yang paling sering dihadapi oleh pengembang saat menjalankan proyek ini:

❌ Error: operator class "gin_trgm_ops" does not exist

Penyebab: PostgreSQL baru belum mengaktifkan ekstensi pg_trgm yang dibutuhkan untuk indeks pencarian cepat barang.

Solusi: Pastikan di awal file migrasi SQL Anda terdapat baris: CREATE EXTENSION IF NOT EXISTS pg_trgm; atau jalankan query tersebut langsung di database Postgres Anda.

❌ Error: ERR_PNPM_OUTDATED_LOCKFILE saat Docker Build

Penyebab: Multi-stage Dockerfile hanya meng-copy root package.json tanpa meng-copy file package.json milik seluruh workspace (apps/backend, apps/frontend, packages/shared) sebelum perintah pnpm install --frozen-lockfile.

Solusi: Periksa apps/backend/Dockerfile dan apps/frontend/Dockerfile, pastikan semua file package.json di-copy terlebih dahulu sebelum menjalankan instalasi dependensi.

❌ Selesai Login Selalu Terpental Balik ke Halaman Login

Penyebab: Anda mengakses web via plain HTTP (misal: http://100.85.157.52:3000), namun backend mengirim cookie dengan atribut secure: true (khusus HTTPS). Akibatnya browser menolak menyimpan cookie tersebut.

Solusi: Set environment variable COOKIE_SECURE=false pada backend Anda.

14. Panduan Menjalankan & Deploy ke Server

A. Menjalankan di Komputer Lokal (Development)

Cukup 3 perintah dari direktori root:

Terminal
# 1. Install semua dependensi monorepo
pnpm install

# 2. Nyalakan database PostgreSQL via Docker
docker compose up -d db

# 3. Jalankan migrasi, seeder, dan server development
pnpm db:migrate
pnpm db:seed
pnpm dev

Akses: Frontend di http://localhost:3000, Backend API Swagger di http://localhost:3001/api/docs.

B. Menjalankan Semua Layanan via Docker Compose (Produksi)

Jika ingin menjalankan seluruh stack (Database, Backend, Frontend, Prometheus, Grafana) dalam kontainer terisolasi:

Terminal
docker compose -f docker-compose.prod.yml up -d --build

C. Menjalankan Pengujian Kualitas Kode (CI Audit)

Terminal
# Menjalankan 288 automated test suite, eslint, typecheck, dan cek raw SVG
pnpm audit:quality

# Memverifikasi 184 internal markdown link dokumentasi
pnpm audit:links
